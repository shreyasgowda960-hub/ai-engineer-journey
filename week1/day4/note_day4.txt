
LISTS
    ordered, changeable collection. reach for it when you have a sequence
    of items that might grow/shrink/reorder.

    fruits = ["apple", "banana", "cherry"]


TUPLES
    ordered like a list, but IMMUTABLE - can't change/add/remove items
    once created. reach for it when data shouldn't change (coordinates,
    RGB, fixed values).

    point = (3, 4)
    point[0] = 5   -> TypeError: 'tuple' object does not support item
                       assignment


DICTIONARIES
    stores key-value pairs. reach for it when you need to look something
    up by a label instead of a position.

    student = {"name": "Alex", "age": 25}
    student["name"]      -> "Alex"

    values can be ANY type (str, int, float, bool, even other lists/dicts)
    mixed freely in the same dict.


SETS
    unordered collection of UNIQUE items - no duplicates allowed. reach
    for it to dedupe, check membership fast, or do set math (union,
    intersection).

    nums = {1, 2, 3, 3, 2}
    print(nums)          -> {1, 2, 3}   duplicates silently dropped

    sets are mutable (.add() / .remove() / .discard()) but adding a
    duplicate does nothing - no error, no change.


INDEXING & SLICING (lists, tuples, strings - NOT sets/dicts)
    fruits[0]     -> first item
    fruits[-1]    -> last item (negative = counts from the end)
    fruits[1:3]   -> slice: start included, STOP EXCLUDED
    fruits[:2]    -> from start up to index 2
    fruits[-2:]   -> last two items


ADDING / REMOVING ITEMS
    list:
        fruits.append("kiwi")     add to end
        fruits.remove("banana")   remove by VALUE (first match)
        fruits.pop()               remove & return last item
        del fruits[i]               remove by INDEX

    dict:
        student["age"] = 20         add/update a key
        del student["age"]           remove a key
        (can only delete by KEY, never directly by value)

    set:
        s.add("x")
        s.remove("x")                error if missing
        s.discard("x")                no error if missing

    IMPORTANT: .append() / .remove() mutate the list IN PLACE and
    return None. print(colors.append(x)) prints None, not the list.
    This is deliberate - Python signals "this mutated, it didn't hand
    back something new". Call them as their own statement, then print
    separately.


LOOPING
    list:
        for color in colors:
            print(color)

    dict - .items() / .keys() / .values() are METHODS (called on the
    dict with dot + parentheses) that give you a view to loop over:
        student.keys()      -> just the keys
        student.values()    -> just the values
        student.items()     -> (key, value) pairs together

        for key, value in student.items():
            print(key, value)

        for key in student.keys():     # same as "for key in student:"
            print(key)

        for value in student.values():
            print(value)


STRING METHODS (pulled forward from Day 5 - needed for word-counter task)
    called as mystring.method()

    case conversion:
        "Cat".lower()          -> "cat"
        "cat".upper()           -> "CAT"
        "cat".title()            -> "Cat"       capitalizes each word

    cleaning:
        "  hi  ".strip()               -> "hi"      trims leading/trailing whitespace
        "cat.".replace(".", "")         -> "cat"     replaces old substring with new

    splitting & joining:
        "hi there".split()              -> ["hi", "there"]     string -> list
        " ".join(["hi", "there"])        -> "hi there"          list -> string

    searching/checking:
        "hello".startswith("he")         -> True
        "hello".endswith("lo")            -> True
        "hello".find("l")                  -> 2      index of first match, -1 if not found
        "cat" in "concatenate"              -> True   membership check

    counting & type checks:
        "banana".count("a")                 -> 3
        "123".isdigit()                       -> True
        "abc".isalpha()                        -> True
